## Problem

A reusable review workflow kept diagnostic artifacts by allowing command steps
to continue, but no terminal job translated retained failures into a failed
caller result. Its summary also copied the event's expected SHA into the
evidence instead of independently observing the checked-out revision.

## Pattern

Evidence retention, revision identity, and the terminal verdict are separate
obligations. A workflow may continue after commands fail solely to serialize
their exits and upload artifacts. It must independently observe
`git rev-parse HEAD`, compare expected, executed, and completion SHAs, and then
run one stable `always()` terminal job that fails eligible runs on missing or
non-success evidence, dependencies, revision equality, or cleanliness.

Known tracked generator side effects need the same proof discipline: establish
a clean `HEAD` baseline before the generator, archive the generated bytes,
restore only that proven baseline, and keep every other mutation visible.

## Candidate skill outline

- Trigger when a reusable workflow uses `continue-on-error`, `always()`
  artifact upload, generated tracked files, or copied event revision fields.
- Treat event SHAs as expectations and repository commands as observations.
- Export deterministic result and revision outputs from the producing job.
- Preserve failed logs and model attempts under run/attempt artifact names.
- Put the required-check name on one final fail-closed job.
- Exercise embedded workflow scripts in temporary Git repositories.
- Falsify mismatch, missing-output, dirty-tree, and generated-side-effect tests.
- Keep unsupported events explicit without weakening eligible-event failure.

## Better path

Design the terminal verdict before adding diagnostic continuation. Model the
summary as a small schema with expected, executed, and completion revisions;
make exact-head labeling conditional on their equality. For each intentional
working-tree side effect, prove the baseline, retain the output, restore the
baseline, and record both operations as statuses rather than adding ignore
patterns. Run the contract suite against both the fixed workflow and targeted
mutations of each new assertion.
