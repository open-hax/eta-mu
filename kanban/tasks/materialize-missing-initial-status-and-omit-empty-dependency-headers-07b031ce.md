# Materialize missing initial status and omit empty dependency headers

## Context

Foresight PR140 native root 4266776916 requests literal initial status on the four original UUID-bearing cutover cards. The current canonical Rheos engine already projects a missing field as incoming, so the finding's claim that Rheos cannot treat them as incoming is not supported by the observed engine. The missing literal metadata remains real. Actual incoming-to-incoming returned a successful no-op without a card or ledger write; repeating that command cannot repair it. Generic frontmatter routes correctly protect status.

Owning source is the Rheos package currently executed from open-hax/eta-mu at 2d24396ec89ab49df335633cc65314992f23cddd. domain/kanban_projection.cljc:12–16 defaults absent status to incoming, and its task projection does not retain the raw frontmatter. infra/transition.cljs:25–26 returns the same-state no-op before reading the file. A projected status therefore cannot prove an explicit persisted status field exists.

The same qualified CLI creates or explicitly clears an empty dependency as literal dependency: []. The user requires omitting empty dependency fields. This five-point owner card incorporates the earlier private two-point rendering proposal without widening the separate roundtrip-planning-metadata card, whose earlier scope intentionally preserved []. It covers source qualification and adoption; actual Foresight mutations belong to separately estimated downstream work.

The current writer writes the card before appending its event. The inspected EDN EventAdmission adapter serializes appends in process but supplies no durable operation identity or reconciliation across card and ledger writes. If event append fails after persistence, present status alone cannot establish a completed initialization. A separately planned and adopted recovery contract is therefore a prerequisite, rather than an undocumented extension of this five-point slice.

## Outcome

An explicit request through the existing canonical status operation can persist a truly absent initial status, while preserving the card's logical state and recording the actual metadata change. New cards and explicit dependency clears omit empty dependency headers. No fake lifecycle hop, general status-edit permission, dependency edge or board implementation is introduced. The owner card closes on its own qualified and adopted source independently of downstream Foresight completion.
